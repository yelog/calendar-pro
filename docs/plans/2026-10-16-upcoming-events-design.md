# 全部日程版块设计

**日期：** 2026-10-16
**状态：** 已实施；含滚动自动加载、「全部日程」五项改造批次、条数分页
交互模型重构与用户反馈批次二（2026-10-17：更名/入口行/显式复位通道/
限高/位置约束/注释清理）
**实现记录：** [2026-10-16-upcoming-events.md](2026-10-16-upcoming-events.md)

## 目标

在菜单栏弹层的日程分节之后新增一个可折叠的「全部日程」版块，以条数
分页展示未来的日历日程（可选包含带到期时间的未完成提醒），下滚浏览
upcoming、下拉回看过去，不必翻日历就能掌握近期安排。

## 信息结构

```text
月份标题
月历网格
统一日期摘要
信息条（天气 / 宜忌）
番茄钟（可选）
日程分节（现有，行为不变）
全部日程分节（新增，可折叠）
分隔线
底部操作
```

## 交互设计

- 分节初始展开态读「默认展开版块」设置（默认展开），标题行只显示
  「全部日程」与当前已加载条目总数（加载中显示"加载中"）。
- 点击标题切换展开，内容区内部滚动，`maxHeight` 240 pt（2026-10-17
  批次二对齐看板分支取值；只约束展开态内容区，不含标题行），超出部分
  在分节内滚动，不再撑长弹层整体内容。
- 展开后按「天」分组升序渲染：天头显示"昨天 / 今天 / 明天 / M月d日"
  （本地化模板），条目行复用 `EventCardView` 的卡片视觉语言，事件点击
  进详情、提醒点击进详情、提醒勾选切换完成状态。
- 条数分页加载（2026-10-17 重构，推翻原「双向时间窗渐进」模型）：
  每页 10 条；弹层每次打开重置到第一页——从当天零点开始（含今天全天）
  的 10 条，过去方向初始 0 条。底部沿用 1 pt 哨兵 `onAppear` 自动加载
  下一页（未来方向，LazyVStack 惰性渲染即"差不多到底"触发）；过去
  方向改为列表最顶部常驻「加载更早」显式入口行（2026-10-17 批次二，
  推翻下拉过拉探针方案）：hasMorePast 时渲染 chevron.up + "加载更早
  日程"按钮行，鼠标/触控板/完全键盘访问均可触发；加载中被进度行替换
  （互斥分支），过去端探明尽头后不渲染；空态文案留在 ScrollView 内，
  入口行不因未来无条目丢失。推翻原因：macOS SwiftUI ScrollView 无
  弹性过拉，真机触控板拖动穿透到弹窗、滚轮到顶无过拉偏移，40 pt
  阈值从未达成，下拉探针方案整体失效。
- 弹层打开重置（2026-10-17 批次二改为显式时序通道）：PopoverController
  每次 show 前递增 `popoverPresentationGeneration`（挂在既有
  refreshNow/checkAndResetIfNeeded 同一接线位置），RootPopoverView
  onChange 该代数触发分页重置与首载；首次打开另有 `onAppear` 一次
  兜底（两路由分方向请求 ID 守卫吸收，不双装载）。数据重置后滚动
  偏移会残留，由重置代数标记驱动 `ScrollViewReader` 显式 `scrollTo`
  回到列表顶。不再依赖分节 `onAppear`：内容视图控制器被复用，重开
  时 onAppear 在真机上不重新触发（真机行为证据：重开后已加载页与
  滚动位置原样保留），不可作为重开信号。
- 折叠状态只记在视图 `@State` 内：初始值取「默认展开版块」设置，
  弹层展示代数变化时按设置重取初值，会话内手动折叠即时生效不持久化。

## 数据层

- `EventService.fetchUpcomingCalendarItems(pastStart:futureEnd:
  enabledCalendarIDs:includeReminders:enabledReminderCalendarIDs:)`：
  - 事件用 `predicateForEvents(withStart: pastStart, end: futureEnd)`
    查询。该谓词是重叠语义，会返回开始早于窗口的事件，因此本地再按
    `startDate >= pastStart 且 endDate > pastStart` 过滤：开始早于过去
    端点的多天事件不纳入（只在其开始日所在的窗口内展示一次）；窗口内
    已结束的事件纳入，供上滚回看过去。过滤逻辑抽为静态纯函数
    `EventService.event(_:isWithinUpcomingWindow:enabledCalendarIDs:)`
    供单元测试覆盖边界。
  - 提醒只取未完成项：复用 `fetchReminders` 的处理思路，用
    `predicateForIncompleteReminders(withDueDateStarting: nil, ending:
    futureEnd)` 兜住基准到期日早于窗口的递归提醒，再在本地按窗口过滤
    并按 `calendarItemIdentifier` 去重。
- 提醒窗口起点取 `pastStart`（初始为今天零点）：当天早些时候已过期但
  未完成的提醒保留在"今天"分组，与日程分节对当天的展示语义一致。

## 纯函数布局

`UpcomingSnapshot.make(items:now:calendar:)` 输入条目数组，输出按天升序的
`[UpcomingDayGroup]`（天头 + 条目）与总数，供视图直接渲染；同一天内全天条目
在前、其余按开始时间升序。过去天同样分组，天头「昨天」独立文案。与
`EventTimelineSnapshot` 的纯函数模式一致，测试注入固定时区的 `Calendar`
即可覆盖。

## 设置项

`MenuBarPreferences` 新增（解码均带缺省回退，旧数据无损升级）：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `showUpcomingSection` | `true` | 是否显示全部日程分节 |
| `upcomingDayLimit` | `90` | 时间上限（天），0 表示不限制 |
| `upcomingIncludeReminders` | `true` | 是否纳入有到期时间的未完成提醒 |
| `upcomingDefaultExpanded` | `true` | 弹层打开时分节是否默认展开 |
| `upcomingEnabledCalendarIDs` | `[]` | 参与聚合的日历，空数组表示全选 |
| `upcomingEnabledReminderCalendarIDs` | `[]` | 参与聚合的提醒列表，空数组表示全选 |

设置项位于独立的「全部日程」设置菜单页（「日程」页之后）；提醒列表
勾选组仅在 `upcomingIncludeReminders` 开启时显示。日历勾选沿用
"空数组=全选"的归一语义。`upcomingIncludeReminders` 默认值调整为 true
时，已存 JSON 显式写入 false 的用户经 `decodeIfPresent` 保持 false，
仅缺失该 key 的历史数据与新用户走 true。

刷新时机：弹层每次打开（弹层展示代数通道，`onAppear` 仅首次兜底）
  重置分页并加载第一页；日历/
提醒授权变化、设置变化、EventKit store 变更与跨天同样重置到第一页
（数据源变化后从第一页重新开始，语义可预期）；选中日期变化不再触碰
全部日程（内容与选中日期无关）；用请求 ID 做竞态保护。原「用户已扩展
的窗口端点在弹层重开时保留」的决定随 2026-10-17 重构推翻。

## 交互模型重构（2026-10-17 用户反馈）

用户对Feat PR #7 提出三条反馈，据此把「双向时间窗渐进」重构为
「条数分页」，推翻两项旧决定：

1. 现状问题：打开弹层即自动连续加载（顶部哨兵初始可见触发过去端自动
   补窗 + 底部哨兵连续加载），等于默认加载全部日程。
2. 新模型：条数分页，每页 10 条；第一页 = 从当天开始（含今天全天）的
   10 条，过去方向初始 0 条；底部滚动差不多到底自动加载下一页（哨兵
   机制沿用）；顶部下拉过拉触发向过去加载一页（过拉超阈值才触发、
   加载中不重复、回弹后再拉）。
3. 弹层每次打开：分页状态重置到第一页 + 滚动位置回到列表顶（推翻
   「窗口端点跨打开保留」）；时间窗渐进模型同时废止（推翻「首窗
   30 天 + 滚动扩窗」），时间范围上限设置（30/90/180/全部）改作未来
   方向的尽头边界。

数据层取数策略：日期游标 + 30 天窗循环查询。未来页从游标起查
`[cursor, cursor+30天)`（裁剪到设置上限），不足 10 条推进游标续查；
过去页对称（无下限，空窗即尽头）。切片/游标推进抽纯静态函数
`RootPopoverView.advanceUpcomingPage`（输入窗内条目序列 + 游标上下文 +
页大小，输出本窗取走条目 + 新游标 + 是否尽头），EventKit 查询薄层
沿用 `fetchUpcomingCalendarItems` 既有谓词。页满时游标停在当前窗起点，
下一页复查同一窗并按 `selectionIdentifier` 身份去重续接页界，页界同刻
条目不重不漏。循环上限保护：单页最多连续查 12 窗（约 360 天），仍未
凑满则返回已有并视为尽头。

## 设计决策与限制

- 分节开关独立于 `showEvents`：全部日程不依赖选中日期，关闭日程分节时
  仍可单独使用。
- 折叠状态不持久化（见交互设计），是有意取舍而非遗漏。
- 递归提醒按"天"近似展开（复用单日判定 `isOccurrence` 逐日检查），未处理
  例外日期（excluded dates）等复杂规则；对"近期 N 天"的展示场景足够。
- 多天事件只在其开始日（不早于窗口过去端点）出现在列表中，不做跨天
  重复展示；开始早于过去端点的多天事件整体不纳入。
- 条数分页防重（2026-10-17）：每页装配期间同方向加载标记置位、哨兵/
  下拉提示被进度行替换（视图层防重），加载中忽略新的加载触发（状态层
  防重）；重置产生的过期结果由既有请求 ID 守卫丢弃。未来端以「游标
  触达设置上限」「单页 12 窗循环保护」判尽头；过去端以「空窗即尽头」
  为启发式（沿用原「扩窗带不回条目即历史起点」），页满后的同窗复查
  带不回新条目不算尽头。
- 已知取舍（2026-10-17）：未来端跨多个 30 天窗的长空档会多查几窗（受
  12 窗上限保护，触顶按尽头处理，重开弹层即恢复）；递归提醒逐窗重复
  返回同一对象，靠身份去重不重复展示，仅由该提醒构成的过去窗不误判
  尽头。过去方向加载入口用显式按钮行而非手势/探针：macOS ScrollView
  无弹性过拉，下拉检测（无论 GeometryReader 还是 `onScrollGeometry
  Change`）在真机不可用；弹层窗口被用户拖出屏幕顶部无回弹（近期
  macOS 的 _NSPopoverWindow 支持按背景拖动），在 popoverDidShow 将
  弹层窗口 `isMovable`/`isMovableByWindowBackground` 置 false 禁止
  拖动，系统每次 show 的程序式定位不受影响。
- 本地化 key 沿用仓库惯例（英文 key，`zh-Hans` 为源语言）；版块相关
  key 随更名迭代（`Recent Events`→`All Events`、`Recent Yesterday/
  Today/Tomorrow`→`All ...` 等，2026-10-17 批次二），"昨天/今天/明天"
  不复用菜单栏 token 的短文案 `Today`（zh 为"今"）。
