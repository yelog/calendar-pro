# 应用时区设计

日期：2026-11-03。关联：GitHub issue #9。状态：已实施；单元测试及原生设置页/时区选项渲染通过，分次验证结果见实施记录。UI 自动化未进入断言，真实 EventKit 数据库写入仍需手动验收。

## 目标

通用设置支持跟随系统（默认）或手动选择 IANA 时区。状态栏、预览、月历、日程查询与时间轴、近期事项、提醒看板和详情使用同一有效时区。切换无需重启，不修改系统设置，不通过 IP 推断时区。

## 选项的 UTC 偏移

时区名称和 IANA 标识之外，下拉选项右侧显示当前 UTC 偏移，例如 `UTC+8:00`、`UTC-3:30`、`UTC+5:45`，零偏移显示 `UTC+0:00`。数值使用等宽字体并右对齐，勾选标记固定留位；名称与标识继续保留，以区分当前偏移相同但夏令时规则不同的时区。

“跟随系统”同样显示实际系统时区的偏移。所有选项使用同一个当前日期快照，通过 `secondsFromGMT(for:)` 计算；打开列表后每分钟更新，正确反映夏令时，不把偏移量持久化或作为时区身份。

搜索同时匹配名称、IANA 标识和显示的 UTC 偏移，支持 `+8:00`、`UTC+8:00`、`-3:30`、`+5:45` 等输入。筛选和行标签使用同一日期快照，避免夏令时切换时结果与偏移显示不一致；保留跟随系统入口。

## 共享上下文

`SettingsStore.timeZoneIdentifier: String?` 独立持久化，nil 表示跟随系统；无效存储值回退为跟随系统。`effectiveTimeZone` 与 `displayCalendar` 提供唯一解析入口，日历使用 Gregorian 并保留每周起始日偏好。SwiftUI 宿主通过 `appTimeContext` 同时注入 calendar 和 timeZone；Foundation 服务继续显式注入 Calendar 或 provider，不修改进程全局默认时区。

## 日期语义

- 固定时区定时事件保留绝对时刻；切换只影响显示及日归属。新建定时事件显式绑定打开编辑器时的时区。
- 全天和 floating 事件以 EventKit 默认时区读取年月日/时分，映射至应用日历；查询先覆盖系统与应用两个日期窗口，再按应用语义过滤，避免漏项或重复归日。
- 提醒有明确 dueDateComponents.timeZone 时保留其含义；timed floating 提醒在应用时区解释，日期提醒保留年月日。不得用全局时差平移所有日期。
- 编辑器捕获固定应用日历；设置变化不重解释未保存草稿。仅改标题/备注保留已有事件原始起止和时区，以及提醒原始日期组件。实际修改日期后再按对应语义转换写入。
- 节假日源中的 UTC 午夜是年月日的存储载体，分组时将其年月日映射至应用日历，不把它作为绝对时刻换区，避免美洲时区漏标。
- 人工浏览日期保持原年月日；跟随今天时切换后重新定位今天。异步查询结果按请求标识及时区校验失效。

## 刷新与边界

设置变化显式触发时间刷新、查询、分页重置和缓存失效。跟随系统响应系统时区、时钟、唤醒通知；固定模式不跟随系统时区跳变。日期运算使用 Calendar，夏令时日不假定为 86400 秒。倒计时的秒数/分钟数保持不变。

时间协调器先写入新的 currentDate，再发布跨天 revision，确保同步订阅者读取新日期。查询捕获通过 IANA 标识冻结的时区，回写时校验请求标识和当前时区。提醒查询保留 nil 起点以覆盖周期规则，结束上界增加 48 小时以覆盖来源/应用时区差异，避免每分钟读取全部未来事项。

原生 EventKit 探针确认：floating 提醒的输出组件需附系统日历，避免 SDK 对内嵌来源日历再次换区；全天写入先设置非全天范围，最后启用 isAllDay，避免变回定时或多覆盖一天。实际转换为全天时，时区按 SDK 规则为 nil；未改日期的保存完全跳过这些 setter。

天气的供应商当地时间与应用显示时区分开，不重构供应商解析。节气继续采用已有北京时间参考规则。番茄钟按秒运行；日统计仅影响此后的日期归属，不重新分配已有聚合历史。
