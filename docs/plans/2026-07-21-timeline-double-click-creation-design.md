# 时间线空白区域双击创建日程设计

## 背景与目标

Calendar Pro 的下拉日程区已经使用真实分钟高度展示全天时间线，但创建入口目前只有顶部“+”按钮，无法表达用户在时间线上指向的具体时间。

本次改动允许用户双击时间线中的空白区域，打开现有创建面板，并将点击位置吸附到对应的半小时区间。创建面板默认选择“日程”，但用户仍可切换为“提醒事项”；提醒事项的到期时间继承该区间的开始时间。

## 交互规则

1. 只有双击时间网格空白区域才触发创建；单击不产生动作。
2. 双击已有日程或提醒事项卡片时，继续执行现有的打开/选择行为，不创建新项目。
3. 点击位置按半小时向下吸附：
   - `10:00–10:29` 对应 `10:00–10:30`。
   - `10:30–10:59` 对应 `10:30–11:00`。
4. 双击后打开现有创建面板，默认选择“日程”，标题输入框继续自动获得焦点。
5. 用户切换到“提醒事项”后，到期日期和时间等于吸附区间的开始时间。
6. 顶部“+”按钮保持原有默认时间行为；只有时间线双击入口使用精确的初始时段。
7. 当选中日期没有任何项目时，仍展示完整时间网格，并保留轻量空状态提示，使空白日也能使用同一创建手势。
8. 只有具备日历创建能力时才启用时间线双击创建，避免呈现无法完成的操作。

## 方案选择

采用 SwiftUI 空间双击手势读取时间网格内的本地坐标。

时间网格背景负责处理双击，现有项目按钮继续位于其上方并优先命中。纵坐标按当前 `1pt = 1 分钟` 的布局比例换算为分钟数，再向下吸附到 30 分钟边界。

未采用以下方案：

- 48 个透明半小时交互块：视图和无障碍节点更多，跨区间卡片的命中层级更复杂。
- AppKit `NSClickGestureRecognizer` 包装：需要维护 SwiftUI/AppKit 坐标和事件透传，超出当前需求复杂度。

## UI / UE / UX 设计

创建面板本身作为双击后的明确反馈，不额外增加提示浮层或装饰动画。这样既符合 macOS 日历类产品的直接操作习惯，也不会给尺寸有限的菜单栏弹层增加视觉噪声。

空白日的“无日程”信息从替代内容调整为时间线上方的辅助提示。时间网格始终提供稳定的空间定位，用户不需要根据日期是否已有项目学习两套创建方式。

项目卡片和空白背景拥有互斥的命中语义：卡片代表查看既有项目，背景代表创建新项目。水平滚动和垂直滚动保持现有行为，单击或拖动不会误触发创建。

## 架构与数据流

新增一个纯逻辑的时间槽计算模型，负责：

1. 将网格纵坐标换算为当日分钟数。
2. 将分钟数向下吸附到 30 分钟槽位。
3. 基于选中日期和 `Calendar` 构建开始、结束时间。
4. 在当日最后半小时返回 `23:30–次日 00:00`。

数据流如下：

`EventListView` 空白网格双击 → 半小时区间 → `CalendarPopoverView` → `RootPopoverView` → 现有详情窗口控制器 → `CalendarItemComposerView`

创建模式扩展为可携带可选初始时间范围。时间线入口传入该范围；顶部“+”入口不传，继续使用 `CalendarEventCreationRequest.makeDefault` 的默认值。

创建器收到精确范围后同时初始化：

- 日程开始时间为槽位开始时间；
- 日程结束时间为槽位结束时间；
- 提醒事项到期时间为槽位开始时间，并包含具体时间。

编辑日程和编辑提醒事项的数据流不变。

## 边界与错误处理

- 坐标限制在时间线有效范围内，避免浮点误差产生负数或超过一天的分钟值。
- 使用 `Calendar.startOfDay(for:)` 和日历加法构造日期，遵循本地时区及夏令时规则。
- 精确落在 `10:30` 边界时进入 `10:30–11:00` 槽位。
- 若没有选中日期或当前不可创建日历日程，则不注册有效创建动作。
- 打开创建面板后的保存错误继续由现有创建器校验和错误提示处理。

## 测试策略

单元测试覆盖：

- 整点上半区、下半区和半小时精确边界；
- 负坐标与超过时间线高度的坐标限制；
- 当天最后半小时跨至次日；
- 创建模式将日程起止时间和提醒时间正确传入创建器初始值；
- 默认“+”入口仍保持原有默认时间行为。

视图和回归验证覆盖：

- 空白日仍渲染时间网格与轻量空状态；
- 双击空白区域打开创建器并预填正确时段；
- 切换到提醒事项后时间等于槽位开始时间；
- 双击已有项目不会创建新项目；
- 时间线滚动和项目单击行为不回归。
